### **1. Port Security**
Zabezpiecza fizyczne porty switcha, limitując liczbę oraz konkretne adresy MAC, które mogą przez dany port wysyłać ruch. Chroni głównie przed atakami MAC Flooding (przepełnianie tablicy MAC switcha, by zamienić go w głupi hub) oraz podłączeniem nieautoryzowanych urządzeń.

#### Konfiguracja i tryby działania:
Przed włączeniem Port Security, port nie może być w trybie autonegocjacji. Musi być ustawiony sztywno jako access (lub trunk).
```
switch(config)# interface f0/1
switch(config-if)# switchport mode access
switch(config-if)# switchport port-security
switch(config-if)# switchport port-security maximum 2
switch(config-if)# switchport port-security mac-address sticky
```
- *Protect*: Switch odrzuca pakiety nieznanego intruza, ale legalne komputery nadal działają. Brak logów o ataku.
- *Restrict*: Działa jak Protect, ale generuje logi Syslog i zwiększa licznik naruszeń.
- *Shutdown*: Port natychmiastowo gaśnie (Stan err-disable). Wyłącza się całkowicie, aż administrator ręcznie go nie zresetuje (komendą `shutdown`, a potem `no shutdown`).

### **2. DHCP Snooping (Ochrona przed fałszywym serwerem)**
Atak *Rogue DHCP Server*: Haker wpina laptop do sieci i uruchamia własny serwer DHCP. Zaczyna rozdawać komputerom adresy IP, podając swój własny adres jako Default Gateway. W efektcie cały ruch w biurze płynie przez laptop hakera, który go podsłuchuje (klasyczny atak Man-in-the-Middle).

**Działanie DHCP Snooping**:
Switch zaczyna uważnie "podsłuchiwać" proces DORA. Dzieli wszystkie swoje porty na dwie kategorie:
- *Trusted*: Porty, pod którymi faktycznie znajduje się legalny serwer DHCP (lub porty uplink do routera). Switch pozwala na przepuszczanie komunikatów z ofertami adresów IP (DHCP Offer).
- *Untrusted*: Wszystkie porty, do których podłączeni są zwykli użytkownicy. Jeśli na takim porcie switch zauważy pakiet DHCP Offer, natychmiast go blokuje.

#### Konfiguracja:
```
switch(config)# ip dhcp snooping
switch(config)# ip dhcp snopping vlan 10
switch(config)# interface g0/1
switch(config-if)# ip dhcp snooping trust
```
(Dodatkowo switch buduje w pamięci DHCP Snooping Binding Database - tabelę mapującą adres IP, adres MAC i numer portu każdego komputera, który poprawnie uzyskał adres. Ta tabela jest krytyczna dla kolejnego mechanizmu.)

### **3. Dynamic ARP Inspection - DAI (Ochrona przed fałszowaniem ARP)**
Protokół ARP (mapujący IP na MAC) nie posiada absolutnie żadnego zabezpieczenia. Jeśli haker wyśle do komputera ofiary ramkę z informacją "Hej, adres IP routera 192.168.1.1 znajduje się teraz pod moim adresem MAC", komputer ofiary w to ślepo uwierzy (atak ARP Spoofing/Poisoning).

**Działanie DAI**:
DAI współpracuje z omówionym wyżej DHCP Snoopingiem. Ponieważ switch, dzięki Snoopingowi, posiada bezbłędną tabelę powiązań (wie, że na porcie Fa0/5 jest komputer z IP 10.0.0.5 i MAC A:A:A), używa tej tabeli jako wzorca.
Gdy haker z portu Fa0/8 spróbuje wysłać sfałszowany pakiet ARP twierdząc "Ja mam IP 192.168.1.1", switch patrzy w tabelę Snooping, widzi niezgodność i odrzuca sfałszowany pakiet ARP.

#### Konfiguracja:
```
switch(config)# ip arp inspection vlan 10
switch(config)# interaface g0/1
switch(config-if)# ip arp inspection trust
```
