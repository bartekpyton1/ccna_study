## **DHCP Client**

W małych oddziałach (SOHO) lub poczas łączenia się z operatorem internetowym (ISP), zewnętrzny interfejs (WAN) routera często nie otrzymuje stałego, statycznego adresu IP. Zamiast tego operator nakazuje pobrać adres z jego serwera DHCP. W tej sytuacji router Cisco zachowuje się dokładnie tak samo, jak zwykły laptop podłączony do domowego Wi-Fi - inicjuje proces DORA.
#### Konfiguracja:
```
router(config)# int 0/1
router(config-if)# ip address dhcp
router(config-if)# no shutdown

router# show ip int b
router# show ip route
```

## **DHCP Relay Agent: Broadcast -> Unicast**

Mechanizm DHCP Relay (w Cisco realizowany komendą `ip helper-address`). Konfigurujemy interfejs routera tak, aby nasłuchiwał pakietów DHCP Broadcast (UDP 67). Gdy router taki pakiet usłyszy, zamiast go odrzucać, pakuje go w standardowy pakiet Unicast (skierowany na konkrenty, znany mu adres IP serwera DHCP) i routuje przez sieć korporacyjną.

*Skąd serwer DHCP wie, z jakiej puli przydzielić adres, skoro pakiet przeszedł przez pół kraju?*
- Kiedy Relay Agent pakuje zapytanie, wstawia do niego swój własny adres IP (z interfejsu, na którym usłyszał Broadcast) w polu GIADDR (Gateway IP Address). Serwer DHCP patrzy na ten adres i na jego podstawie dobiera odpowiedną pulę.
#### Konfiguracja:
```
router(config)# int g0/0.10
router(config-subif)# ip address 192.168.10.1 255.255.255.0
router(config-subif)# ip helper-address 10.100.1.50

router# show ip int g0/0.10
```
