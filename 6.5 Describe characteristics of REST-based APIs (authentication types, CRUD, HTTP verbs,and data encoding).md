REST to najpopularniejszy obecnie standard tworzenia interfejsów API (szczególnie Northbound API), dzięki któremu skrypty, aplikacje i kontrolery (np. Cisco DNA Center) mogą łatwo i bezpiecznie wymieniać między sobą dane przez sieć.

Rest nie jest protokołem samym w sobie, lecz zbiorem zasad architektonicznych. Ponieważ bazuje na dobrze znanym protokole HTTP(S), jest niesamowicie lekki, elastyczny i łatwy w implementacji.

Fundamenty REST API:

### **Paradygmat CRUD i czasowniki HTTP (HTTP Verbs)**
API oparte na REST służy do zarządzania zasobami (Resources) - zasobem może być lista routerów, użytkownik, czy reguła na firewallu.
W programowaniu każdą operację na danych można sprowadzić do jednego z czterech działań, znanych pod akronimem CRUD (Create, Read, Update, Delete).

W architekturze REST, akcje CRUD mapuje się bezpośrednio na standardowe metody (czasowniki) protokołu HTTP:
- *Create*: Wykorzystuje czasownik `POST`. Służy do dodawania nowego zasobu do bazy. Przykład `POST /api/v1/users` (tworzy nowego użytkownika).
- *Read*: Wykorzystuje czasownik `GET`. Służy do dodawania nowego zasobu do bazy. Przykład: `GET /api/v1/devices` (pobiera listę urządzeń sieciowych).
- *Update*: Wykorzystuje czasowniki `PUT` lub `PATCH`.
	- `PUT` nadpisuje całkowicie cały zasób nowymi danymi.
	- `PATCH` aktualizuje tylko wybrane pola (np. zmienia sam numer portu, nie ruszając reszty konfiguracji).
- *Delete*: Wykorzystuje czasownik `DELETE`. Usuwa zasób ze wskazanego adresu.

### **Formatowanie Danych (Data Encoding)**
Aby klient (twój skrypt) i serwer (Kontroler SDN) mogły się dogadać, muszą przesyłać dane w ustalonym formacie zwanym ładunkiem (Payload). Choć REST technicznie pozwala na użycie XML lub czystego tekstu, we współczesnych sieciach standardem stał się JSON (JavaScript Object Notation).
Jest on wysoce czytelny dla maszyn (łatwo go parsować w Pythonie) i stosunkowo przyjazny do czytania przez człowieka.
