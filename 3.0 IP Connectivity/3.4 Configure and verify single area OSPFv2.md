___


## 3.4.a **Router ID**

Proces OSPF musi jednoznacznie identyfikować każdy router w topologii za pomocą 32-bitowego adresu, który formatem przypomina adres IPv4 (np. `1.1.1.1`). Router wybiera swój identyfikator na podstawie sztywnej hierarchii (od najważniejszego):
- *Ręczna konfiguracja*: Komenda `router-id` wpisana przez adminstratora (absolutnie zalecana praktyka na egzaminie CCNA).
- *Najwyższy adres IP interfejsu Loopback*: Jeśli ID nie jest ustawione ręcznie, router wybiera najwyższy aktywny adres na logicznych interfejsach Loopback.
- *Najwyższy adre IP fizycznego interfejsu*: Ostatnia deska ratunku. Router wybiera najwyższy adres IP spośród wszystkich podniesionych (up/up) portów fizycznych. Zmiana Router ID wymaga zrestartowania procesu OSPF komendą `clear ip ospf process`.
___


## 3.4.b **Neighbor adjacencies**

Zanim OSPF zacznie wymieniać trasy (LSA), routery muszą się odnaleźć i stworzyć relację sąsiedztwa. Używają do tego pakietów *Hello*, wysyłanych domyślnie co 10 sekund na adres multicastowy `224.0.0.5`. Aby routery mogły zostać sąsiadami (osiągnąć stan *Full*), ich konfiguracja musi być w 100% zgodna w kilku kluczowych parametrach. Muszą mieć ten sam numer *Area* (dla Single Area CCNA jest to zazwyczaj `area 0`), takie same timery (Hello i Dead), znajdować się w tej samej podsieci z identyczną maską (dla środowisk rozgłoszeniowych) oraz posiadać zgodne hasła uwierzytelniające (jeśli są skonfigurowane).
___


## 3.4.c **Point-to-Point**

Jest to typ sieci OSPF stosowany na łączach, gdzie po obu stronach kabla znajduje się dokładnie jeden router (tylko dwóch uczestników). Na takich łączach protokół OSPF nie musi martwić się o optymalizację ruchu i zalewanie sieci pakietami. W sieci typu Point-to-Point nie odbywają się wybory *DR/BDR*. Skonfigurowanie tego trybu na łączach Ethernet między  routerami znacząco przyśpiesza proces zbieżności (convergence) sieci.
___


## 3.4.d **Broadcast (Wybór DR i BDR)**

Środowiska Ethernet to domyślnie sieci rozgłoszeniowe (Broadcast). Jeśli podłączymy 5 routerów do jednego przełacznika, nawiązywanie relacji "każdy z kazdym" wygenerowałoby ogromną ilość niepotrzebnego ruchu. OSPF optymalizuje to, przeprowadzając wybory:
- *DR (Designated Router - Router Wyznaczony)*: Pełni rolę dyrektora. Zbiera informacje od wszystkich routerów i rozsyła je do reszty.
- *BDR (Backup DR)*: Zastępca, który przejmie rolę DR w razie jego awarii.
- *DROTHER*: Zwykłe routery. Nawiązują pełne sąsiedztwo (stan Ful) tylko z DR i BDR, a między sobą pozostają w stanie 2-Way.

*Proces wyborów*: Zwycięża router z najwyższym Priorytetem OSPF na danym interfejsie (domyślnie wszystkie mają priorytet równy 1; router z priorytetem 0 nigdy nie weźmie udziału w wyborach). Jeśli priorytety są równe (remis), wygrywa router z najwyższym Router ID. Wybory DR/BDR w OSPF nie mają prawa preempcji - jeśli do sieci podłączysz lepszy router (z wyższym priorytetem), nie odbierze on roli aktualnemu DR, dopóki obecny DR nie ulegnie awarii.
___

#### Komendy:

**Podstawowa stara konfiguracja OSPF i Router ID**:
```
router(config)# router ospf 1
router(config-router)# router-id 1.1.1.1
router(config-router)# network 10.0.0.0 0.0.0.255 area 0
```
___

**Nowoczesna konfiguroacja OSPF bezpośrednio na interfejsie (preferowana na CCNA)**:
```
router(config)# interface g0/1
router(config-if) ip ospf 1 area 0
```
___

**Konfiguracja Point-to-Point (optymalizacja dla łączy bezpośrednich Ethernet)**:
```
router(config)# interface g0/1
router(config-if)# ip ospf network point-to-point
```
___

**Manipulacja wyborami DR i BDR (Priorytet)**:
```
router(config)# interface g0/1 
router(config-if)# ip ospf priority 200
```
___

**Weryfikacja (Najważniejsze komendy show dla OSPF**:
```
router# show ip ospf neighbor
router# show ip ospf interface g0/1
router# show ip route ospf
router# show ip protocols
```
