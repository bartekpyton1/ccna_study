CCNA wymaga umiejętności odróżnienia, do jakich zadań zostały zaprojektowane te dwa popularne narzędzia typu Infrastructure as Code (IaC).

### **Infrastructure as Code (IaC) - Koncept**
Tradycyjne konfiguracje sieci tworzyło się poprzez ręczne logowanie do CLI routera. Dziś konfigurację deklaruje się w formie kodu zapisanego w pliku tekstowym, który można trzymać w systemie kontroli wersji (np. GitHub). Narzędzia IaC biorą ten kod i automatycznie budują lub zmieniają środowisko produkcyjne, aby odpowiadało zapisom w pliku.
___


### **Pary Klucz-Wartość (Key-Value Pairs)**
To najmniejsza jednostka informacji w JSON. Po lewej stronie zawsze znajduje się  nazwa atrybutu (klucz) w cudzysłowie, po niej następuje dwukropek, a po prawej stronie jej wartość.
Wartość może przyjąć kilka podstawowych typów danych:
- *String*: Zawse w cudzysłowie. (np. `"hostname": "Router1"`)
- *Number*: Pisana luzem, bez cudzysłowów. Może być całkowita lub ułamkowa. (np. `"vlan_id": true`)
- *Boolean*: Używane często jako przełączniki. Pisane luzem, małymi literami. (np. `"is_active": true`)

Zasada formatowania: każda para klucz-wartość musi być oddzielona od kolejnej przecinkiem (z wyjątkiem ostatniej pary w bloku).
___


### **Obiekty (Objects)**
Obiekt to poprostu logicznie zgrupowany zbiór par klucz-wartość (np. opisujący pojedynczy interfejs routera).
Obiekty zawsze otwieramy i zamykamy nawiasami klamrowymi `{ }`. Obiekty można zagnieżdżać jeden w drugim.
*Przykład*:
```
{
"interface_name": "GigabitEthernet0/0",
"ip_address": "192.169.1.1",
"is_up": true
}
```
___


### **Tablice (Arrays)**
Tablica to lista wielu elementów (najczęściej lista wielu obiektów tego samego typu). Jeśli chcesz zadeklarować, że router ma kilka interfejsów, używasz tablicy. Tablice zawsze otwieramy i zamykamy nawiasami kwadratowymi `[ ]`.
*Przykład*:
```
{
	"router_name": "R1",
	"interfaces": [
		{
		"name": "GigabitEthernet0/0",
		"ip": "10.0.0.1"
		},	
		{
		"name": "GigabitEthernet0/1",
		"ip": "172.16.0.1"
		}
	]
}
```
___


### **Na co uważać**
Na egzaminie Cisco lubi pokazywać fragmenty źle sformatowanego JSON-a i prosić o znalezienie błędu. Najczęstsze pułapki to:
- *Brakujące przecinki*: Zobacz, czy każda linijka (poza ostatnią w klamrze) kończy się przecinkiem.
- *Złe nawiasy*: Zobacz, czy lista jest objęta w `[ ]`, a cechy urządzenia w `{ }`.
- *Cyfry w cudzysłowiu*: Jeśli widzisz `"vlan": "10"` to jest to String, a nie Number. Choć to błąd typowania, sam JSON jest poprawny syntaktycznie. Gorszym błędem jest brak cudzysłowów wokół wartości tekstowej, np. `"name": GigabitEthernet` (brak cudzysłowów przy słowie GigabitEthernet wywali błąd składni JSON).
