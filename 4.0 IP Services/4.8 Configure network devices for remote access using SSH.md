**SSH (Secure Shell)**: to protokół działający na porcie TCP 22, który całkowicie zastąpił przestarzały Telnet (TCP 23). W przeciwieństwie do Telnetu, który przesyła całą komunikację (w tym hasła) otwartym tekstem, SSH szyfruje cały ruch, chroniąc przed podsłuchem (sniffingiem).

Aby uruchomić SSH na czystym urządzeniu Cisco, musisz wykonać cztery obowiązkowe kroki, ponieważ proces ten przypomina budowanie domku z kart - pominięcie jednego etapu uniemożliwi przejście do kolejnego.

#### Konfiguracja:

1. **Unikalna tożsamość urządzenia (Prerequsites)**
	Router nie może wygenerować certyfikatów kryptograficznych (kluczy), jeśli nie posiada swojej unikalnej nazwy w sieci. Domyślna nazwa `Router` jest odrzucana przez system. Musisz zmienić nazwę urządzenia oraz przypisać mu nazwę domeny.
	```
	router(config)# hostaname R1
	R1(config)# ip domain-name firma.local
	```


2. **Generowanie kluczy kryptograficznych (RSA)**
	To najważniejsza komenda. Uruchamia ona algorytm matematyczny, który tworzy parę kluczy (publiczny i prywatny) używanych do szyfrowania sesji.
	```
	R1(config)# crypto key generate rsa
	```


3. **Stworzenie lokalnego konta administratora**
	Z racji tego, że dostęp będzie zdalny i bezpieczny, potrzebujemy konkretnego loginu i hasła. Używamy parametru `secret`, który w przeciwieństwie do `password`, bezpiecznie hashuje hasło w pliku konfiguracyjnym (używając algorytmu MD5 lub SHA-256).
	```
	R1(config)# username admin privilege 15 secret cisco123
	! Opcjonalny parametr `privilege 15` sprawia, że po zalogowaniu od razu trafiamy do trybu uprzywilejowanego `#` z pominięciem trybu `>`
	```


4. **Zabezpieczenie wirtualnych linii (VTY)**
	Line VTY (Virtual Teletype) to wirtualne porty służące do zdalnego zarządzania. Domyślnie urządzenia Cisco wpuszczają prze nie ruch Telnet.
	```
	R1(config)# line vty 0 4
	R1(config-line)# login local
	R1(config-line)# transport input ssh
	```


5. **Wymuszenie SSHv2 (opcjonalnie, ale warto)**
	Domyślnie router może obsługiwać wersje 1.99, która pozwala na łączenie się zarówno starym klientom v1, jak i nowym v2. Ze względów bezpieczeństwa zawsze wymuszamy wersje 2.
	```
	R1(config)# ip ssh version 2
	```


**Komendy weryfikacyjne**
```
R1# show ip ssh
! Pokazuje globalny status usługi: wersję protokołu, timeouty sesji oraz liczbę dopuszczalnych błędnych prób logowania.

R1# show ssh
! Pokazuje listę aktualnie trwających, aktywnych sesji zdalnych, nazwy zalogowanych użytkowników i używane algorytmy szyfrowania.
```


**Połączenie się z innego urządzenia**
```
PC# ssh -l admin 192.168.0.1
```
